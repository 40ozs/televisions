# Benchmark Report — VintageFilmAudio MVP

Machine: 4-core x86-64 Linux container (Ubuntu 24.04, GCC 13.3, Release -O3).
Method: `Tests/Performance/PerfTest.cpp` — full Engine chain, stereo, default
magnetic-film/Academy state, ~250 ms of audio per cell after warm-up; average
and worst-case per-callback time. Raw data: `TestOutput/perf.json`
(regenerated by `./build/VintageFilmAudio/VfaDspTests Perf`).

## Standard quality — % of real-time budget (average, measured)

| Block | 44.1 kHz | 48 kHz | 96 kHz | 192 kHz |
|---|---|---|---|---|
| 16 | 6.5 % | 6.9 % | 17.2 % | 38.9 % |
| 64 | 6.0 % | 6.5 % | 16.1 % | 38.3 % |
| 256 | 6.1 % | 7.4 % | 16.5 % | 36.9 % |
| 512 | 5.8 % | 6.8 % | 15.7 % | 37.0 % |
| 2048 | 5.8 % | 6.3 % | 15.4 % | 37.7 % |

Worst-case callbacks stay within ~3× the average (scheduler noise on a
shared container; no algorithmic spikes observed).

## Quality-mode cost (measured, 48 kHz / 512)

| Mode | avg µs / block | % budget |
|---|---|---|
| Eco (1× OS, 129-tap FIR) | 499 | 4.7 % |
| Standard (2× OS, 257-tap FIR) | 722 | 6.8 % |
| High (4× OS, 513-tap FIR) | 1034 | 9.7 % |

## Other measurements

- Memory: engine + both FIR paths + delay lines ≈ a few MB per instance
  (dominated by JUCE oversampling buffers and the 400 ms print-through line).
- Startup (prepareToPlay incl. synchronous delivery design): ~2 ms at 48 kHz.
- Preset switch: parameter writes only (message thread); the audio thread
  cost is a normal transition ramp (5 ms) plus one staged FIR redesign
  (~0.4 ms on the message thread).
- Regression guard: PerfTest FAILS if Standard 48 kHz/512 exceeds 50 % of the
  real-time budget on the build machine.

Numbers are from the reference container and will differ on end-user
hardware; the guard threshold, not the absolute numbers, is the contract.
